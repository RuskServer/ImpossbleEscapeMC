# タスクの納品・完了報告

レイド参加中は、タスクのアイテム納品と完了報告（報酬受領）を行えない。画面には「納品・報告はレイド終了後に行えます」を表示し、該当する操作ボタンを出さない。タスクの閲覧・受領、討伐・探索などの目標進捗は継続する。

## 判定と実行時の保護

`QuestDeliveryAccess` が `RaidModule.isInRaid` の参加状態を参照する。ワールド名や現在位置では判定しないため、脱出・死亡後に参加状態が解除されれば、リザルト画面から通常どおり納品できる。

以下の入口と実行処理で再判定する。

- `/quest handin` は手持ちアイテムを読む・消費する前に拒否する。
- 個別・一括納品画面は開始時と実際の納品前に拒否する。参加前に開いた画面の遅延操作も拒否し、納品セッションを閉じる。
- リザルトの納品は `QuestAutoHandIn.apply` で保管先の読み書き前に拒否する。
- `HAND_IN` イベントと納品目標自身も進捗更新を拒否する。
- 完了報告の画面操作と `QuestModule.completeQuest` は報酬付与・完了記録前に拒否する。

拒否時には所持品、納品進捗、完了記録、報酬を変更しない。レイド中の操作には理由をチャットで通知する。

## 検証

`QuestRaidDeliveryTest` は実際のコマンド、ダイアログ操作、目標、イベント、リザルト納品、完了処理を呼び、レイド中はインベントリに触れず進捗・報酬が変化しないことを検証する。参加前の古い画面操作、討伐・探索の継続、参加状態解除後の納品・報酬付与も確認する。

実サーバーではレイド中の PDA、参加前に開いた画面、脱出後のリザルトからそれぞれ操作を確認する。
