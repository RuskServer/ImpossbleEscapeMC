# SCAV救援の交戦単位上限

`ScavHelpEncounter` は交戦ごとのUUIDを保持し、サーバースレッド上で扱う。現在の上限は次の2つ。

- 救援を受諾した累計個体数は2体まで（`MAX_REINFORCEMENTS`）。
- 直接発見した個体も含め、交戦グループのメンバーは3体まで（`MAX_COMBATANTS`）。

救援受諾で枠を消費し、元の交戦グループを継承する。救援者が接敵して自分も助けを呼んでも、同じ枠を使う。同じ敵UUIDを独立して発見した個体も登録済みの交戦を参照し、総員3体に達していれば `enterCombat()` は失敗する。

接敵・離脱・死亡で枠を返さない。交戦中の補充による増員を防ぐ。既存の救援者の呼び直しは追加消費せず期限だけ更新できる。対象を切り替えても、有効な既存交戦の枠を保持する。

最後の接触・被弾から200tick（20TPSで10秒）で交戦を失効させ、次の交戦では枠を新設する。別々の交戦を統合する時は、重複を除いたメンバーの合計が3体以内でなければ統合を拒否する。収まる場合はメンバーと消費済みの救援枠を合算し、捜索地点の予約を解除して競合を避ける。

これは交戦登録の制限であり、ワールド全体で戦えるSCAVを常に3体に固定するものではない。異なる対象IDの交戦、音だけの独立捜索、既存対象や被弾からの入口などは区別する。視認報告の内容・救援先の優先度・捜索分担は [SCAV_COORDINATION.md](SCAV_COORDINATION.md)、全体の実行順序と制約は [scav_ai_specification.md](scav_ai_specification.md) を参照。

## 検証

`ScavHelpEncounterTest` は援護2体・総員3体、同じ救援者の更新、救援連鎖、独立接敵の拒否、枠維持、200tick境界、新交戦、対象切替、許可される交戦統合、攻撃者不明の場合を確認する。

テストは交戦枠の判定を検証する。実サーバーでの同時接敵・複数の敵ID・視認と被弾の入口を含む挙動は、AIログと合わせて確認する。
