# ボス定義とレイド配置

高脅威区域に登録した専用地点へ、ボス1人と護衛2人を1部隊として出す。通常SCAVのスポーン地点・装備抽選・再湧きとは分ける。データパック・リソースパックは変更しない。

## 出現

`BossCatalog.java` の `spectre_commander` が既定のJava定義。enabled=true、maps=[ノヴォザリエ薬品工場]、chance=0.125。編成・装備・抽選条件はコードで管理する。chanceは0～1の有限値。範囲外では出現しない。対象マップに有効な3人分の登録がある時、新しいRaidInstanceで1回だけ抽選する。複数区域の登録があっても、候補から1区域を選び、マップ全体で最大1部隊。参加者ごと・接近ごとの抽選はしない。

当選しても、3地点すべてが安全になるまで生成を待つ。少なくとも1人がいずれかの地点から64ブロック未満へ接近し、観戦者・銃用FakePlayer以外のワールド内プレイヤー全員について、3地点とも24ブロック以上離れ、80ブロック未満で足・胴・頭のいずれにも視線が通っていないことを確認する。既存のSCAVスポーンと同じ視認判定を使用する。3地点のチャンク、頭・肩の空間と足場を実際のブロック形状で確認する。未読込チャンクをロード・生成しない。

スポーンを試す直前に抽選権を消費する。1人でも銃・必須装備・弾の生成に失敗した時は、それまでに生成した部隊員を削除し、同じレイドでは再試行しない。倒した後の再湧きや、プレイヤーが離れてから戻った時の再生成もない。出現した部隊は通常SCAVの距離デスポーン対象に入れない。レイド終了・周期リセット・サーバー停止で全員を回収する。

ボス部隊のMob自体も永続化しない。再起動で途中のレイドを復元する場合、ボスの抽選・再生成を抑止する。倒した部隊や使われた装備の復活を避けるため、当選待ちや生存中だった部隊もその継続レイドでは復元しない。次の新規レイドから再び抽選する。

## 地点登録（OP）

最初に `/raid danger list ノヴォザリエ薬品工場` で区域IDを確認する。高脅威区域がまだ無ければ、WorldEdit/FAWEで選択して `/raid danger add <mapID> <zoneID> [表示名]` で登録する。

その区域内の、安全な足場のある3地点にそれぞれ立って実行する。

```text
/raid boss set ノヴォザリエ薬品工場 <zoneID> boss
/raid boss set ノヴォザリエ薬品工場 <zoneID> guard1
/raid boss set ノヴォザリエ薬品工場 <zoneID> guard2
/raid boss list ノヴォザリエ薬品工場
```

護衛2人はボスの左右、遮蔽のある位置などへ手動配置する。地点間は1.5ブロック以上、護衛はボスから12ブロック以内。3地点が揃い、全員が区域内に収まった登録だけ抽選対象。listは未登録・区域外・間隔不足も表示する。登録・削除・配置の変更は次の新規レイドへ適用する。Java定義の変更はビルドしたプラグインへ差し替え、再起動して反映する。

`/raid boss remove <mapID> <zoneID>` はその部隊の地点だけを削除する。区域自体は残す。`/raid danger remove` で高脅威区域を削除した場合は、対応する部隊地点も削除する。地点は既存のマップJSONへ保存する。旧JSONのbossGroups未定義・nullは空として扱う。Java定義のmapsで出現対象のマップIDを指定する。

## 装備と戦闘

| 役割 | 銃 | AI |
|---|---|---|
| ボス | SCAR-H | HIGH |
| 護衛1 | M4A1 | MID |
| 護衛2 | AS VAL | MID |

全員Altyn（頭・顔、クラス4）、SP-V（胴・腕、クラス5）、Pilgrimを装備する。防具と銃は生成時は完品。弾はそれぞれの口径で貫通クラスが最上位のもの、同クラスなら威力の高いものを選ぶ。予備は3マガジン分。通常SCAVのプレイヤー防具に応じた弾薬クラス上限とクラス4防具の出現数制限には混ぜない。体力40・移動速度は通常SCAVと同じ。通常のLOW/MIDスポーン比率も変えない。

部隊内だけで既存の視認共有・援護を使う。ボスは援護役、護衛は前衛役を維持し、通常SCAVとは役割・救援を組まない。登録した左右の配置を基準に行動し、固定隊列を常に維持する追従AIではない。

ボスは登録地点の水平8ブロック、護衛は各登録地点の水平12ブロック、高さ差6ブロックまでを持ち場とし、さらに高脅威区域の境界で制限する。AI更新の前後で、現在位置・経路の未消化地点・直接移動先・ピーク先を確認する。範囲外の追跡・音への捜索・巡回等を中断し、元の地点へ歩いて戻る。帰還中は発射を止め、瞬間移動は行わない。持ち場内から区域外の相手を撃つことは可能。物理的なノックバックや経路指示後の移動を完全に囲い込む境界ではない。戻る経路が無い場合や、区域端の狭い通路は実地調整する。

装備を報酬にする。死亡時は既存の死体生成へ実装備・銃の残弾・残った予備弾を渡し、戦闘で減った耐久を回復しない。明示的にleader=trueの個体だけBOSSキル集計へ入り、護衛はSCAVキルになる。AIがHIGHでも、護衛や通常SCAVはBOSS扱いしない。SP-Vは現在のラグドール部位モデルの対応外なので、この装備の死体は従来通り通常Mannequin表示へフォールバックする。

## 検証と実機確認

BossPolicyTestとRaidBossPolicyTestは一度だけの抽選、12.5%境界、復元・無効設定、旧JSON、登録の複製防止・区域と間隔、持ち場の範囲、部隊生成途中の失敗回収を確認する。RaidBossSpawnSafetyTestは足場・頭上・肩の障害物・未読込チャンク・液体・世界の高さを確認する。ScavBossAmmoTestは実際の弾カタログからの口径別最上位選択と、弾未定義での生成拒否を確認する。既存の照準、ピーク、判断安定性、射線回復、音の境界も確認する。

実機では3地点登録後、Java定義で検証用にchanceを1にした新規レイドで生成を確認し、その後0.125へ戻す。目の前湧き、3人の連携、区域外への誘導、死体からの装備・残弾回収、討伐後の再湧きなし、レイド終了時の清掃を確認する。生のマップ座標・管理サーバー情報はこの文書へ記載しない。

## 独立した定義と追加編成

`BossModule`はRaidの型に依存しない。`BossDefinition`が編成、`BossPlacement`が役割別の座標、`BossTerritory`が活動区域を表す。`BossEncounter`が抽選結果、安全待ち、全員生成または回収、死亡した構成員の除外、終了処理を所有する。レイドは開始時に配置と区域のコピーを渡し、tickと終了時のcleanupを呼ぶ。モジュール停止時にも残った遭遇を回収する。

[BossCatalog.java](../src/main/java/com/lunar_prototype/impossbleEscapeMC/modules/boss/BossCatalog.java)へ`BossDefinition`を追加し、`create()`が返すMapへIDと定義を登録する。IDと役割名は英小文字・数字・ハイフン・アンダースコア。各定義はname、enabled、maps（マップIDのSet）、chance、membersを持つ。membersは任意の人数・役割名を持てるが、leader=trueは必ず1人。各役割にはgun、brain（LOW/MID/HIGH）、health、radius、ammo、任意のhelmet/chest/backpackを指定する。ammoは`best`で口径内最上位、アイテムIDで指定弾。指定弾の口径不一致や、指定した必須装備の欠落では部隊全体の生成を中止する。防具/バックパックをnullにするとその部位を装備しない。弾の予備は3マガジン。定義の構造はコンストラクタで検証し、chanceの範囲外・非有限値は従来どおり落選として扱う。

ボス定義ファイルの読み書きは行わない。旧config.ymlのraid-bossキーや試作のbosses.ymlがサーバーに残っていても参照しない。配置座標は引き続きコマンドで登録し、マップJSONへ保存する。

```text
/raid boss set <mapID> <zoneID> <boss-id> <role>
/raid boss remove <mapID> <zoneID> <boss-id>
/raid boss list <mapID>
```

boss-idを省略したsetはspectre_commanderの役割を操作する。省略したremoveはその区域の全編成を削除する。listはIDと役割別座標、未完成・未知の定義も表示する。全役割の登録、区域内、地点間1.5ブロック以上、leaderから各護衛12ブロック以内が必要。複数定義・配置があっても、有効な配置を均等に1つ選んでからその編成のchanceを1回だけ抽選する。配置数は個々の出現比率に影響する。

保存先は既存マップJSONのbossGroupsのまま。旧boss/guard1/guard2配列はspectre_commanderとして読む。編集後はbossIdとpositionsへ移行し、未編集の座標・yaw/pitchを保持する。高脅威区域を削除すると、その区域の全定義の配置も削除する。

BossDefinitionTest、BossEncounterTest、BossKillClassificationTestは任意人数・leaderの順序・構造検証、視認/距離/未読込待機、復元抑止、失敗時の全員回収、二重cleanup、PDCの役割による討伐分類を確認する。
