# 自然な光と色に近づける描画改良

目標はSTALKER 2、Cyberpunk 2077のパストレーシング、Cyclesで見られる、光源・反射・遮蔽がつながった空間の見え方。今回は既存のサーバー光とリソースパックのポスト処理を拡張する。

## 既存の構成と今回の変更

`SunShadowService` は近傍の48×16×48ブロックについて太陽の可視性、ブロック光、12方向の1回反射を計算し、圧縮した格子をクライアントへ送っている。格子の1マスは面の向きやRGB反射率を持たず、シェーダーが倍率と光の種類を補間して適用する。

旧反射処理はヒットした面の前の空気にある日光の量をそのまま使い、面に背を向ける日光まで跳ね返していた。レイが最後に通過した軸からヒット面の外向き法線を取り、日光の入射を `max(dot(normal, sun), 0)` で重み付けする。途中の部分透過ブロックも透過率を掛け、低透過率の経路を打ち切る。既存のスナップショット・非同期計算・更新間隔・データ容量・パケット形式は維持する。ブロック光は方向を持たないスカラーのままなので、今回の面の入射補正は日光に対するもの。

リソースパックには `iem:post/indirect` を追加する。深度から復元した近くの面の位置・法線と、その面の画面上の色を使い、面どうしが向き合う場合の色の回り込みと接地の遮蔽を求める。固定4標本、最大半径1.25ブロック。候補との間の2点も確認し、途中に手前の遮蔽物があれば色を集めない。12〜24ブロックで効果を減らす。

画素ごとのRGB反射光は各成分0.08以下、接地の暗さは15%以下。ガンマ2.2による光量の近似空間で合成し、暗い面を一定の白い光で持ち上げない。空・一人称の手・有効な深度や法線がない場所には追加効果をかけない。履歴を使わず、固定標本なので時間ノイズと残像を追加しない。

既存 `light.fsh` の深度・法線復元を `iem_surface.glsl` にまとめ、同じ規則で細い輪郭や深度の飛びを除外する。間接光は480×270、サーバー光の段は960×540で求め、画面側で深度を比較しながら拡大する。通常・暗視・バイザー・雨の全12種のgradeに同じ段を入れる。反射光の元はバイザーの汚れが入る前のワールド画像を使う。

## 調整と比較

パックの `tools/post_effects.py` が設定と段の並びの正本。`python tools/post_effects.py contents` で再生成する。`IndirectConfig` は次の値。

| 設定 | 初期値 | 用途 |
| --- | ---: | --- |
| Radius | 1.25 | 近傍の探索半径（ブロック） |
| BounceStrength | 1.1 | 画面から集める反射光の強さ |
| ContactStrength | 0.6 | 接地の遮蔽の強さ |
| MaxBounce | 0.08 | RGBごとの反射光の上限 |

BounceStrengthとContactStrengthを両方0にすると、この段の見た目を無効にして比較できる。処理コスト自体は残る。半径を0にすると早期終了する。反射光の設定と、以下のグレーディング設定は個別に調整する。光の表の一律補正は維持する。

## 検証

- `SunBounceTest`: 実際のレイと壁で、正面・背面・平行・斜めの日光、夜のブロック光、部分透過、吸収する面を確認。
- `SunShadowServiceTest`: 日なた・日陰・室内・夜の光源・遠景・圧縮データの互換性を確認。
- `tools/check_shaders.py`: 対象クライアントのincludeを使い、IEM_MOD有無を含む164組をVulkan向けにコンパイル。今回変更しないSodium固有の地形2段は、この実行では対象外。
- frameとlight/indirect/gradeの組をVulkan向けにリンクし、SPIR-Vを検証。
- 実際のindirectフラグメントをGPUで実行し、出力の有限性・上限、空と一人称の手の除外、mod有無を確認。部屋の角を生成した比較画像で接地と面間の寄与も確認。
- 同じ検証場面で、入力1920×1080、追加段960×540、RTX 3060の測定は約0.2〜0.3ms。フラグメントの試験はOpenGLドライバ上で行った値で、MinecraftのVulkan実行時の全体性能や実マップの最悪負荷を保証しない。既存gradeへの合成を含む同場面の増分は約0.3〜0.4ms。実際の旧・新gradeフラグメントでも、追加段が中立値なら従来出力を維持すること、空・手の深度で出力差が出ないことを確認した。

## 残る範囲と実機確認

これはLDR画面を用いた小さな拡散反射の補助。正確なアルベド・材質・粗さ・HDR放射輝度を受け取るG-bufferや、ワールド全体の加速構造を持つパストレーサーではない。画面外・裏側・透明面を正確に追えず、カメラの向きで反射の寄与が変わる可能性がある。遮蔽の2点確認も厳密な可視性証明ではない。サーバー格子の光を基本とし、画面からの寄与は近距離に限定する。

金属の鏡面反射、ガラスの屈折、画面外の色反射、多段反射、正確なHDR・露出・トーンマッピングは次段階。これらには材質の入力と描画経路の拡張を検討する。大きな実装へ進む前に、実マップで窓際の室内、壁と床、暗室、夜、細いフェンス、銃とADS、暗視、バイザー、画面端とカメラ移動を比較する。現在の比較画像は生成した検証用の場面で、Minecraftの実機キャプチャではない。

参考: [PBRTの拡散反射モデル](https://www.pbr-book.org/3ed-2018/Reflection_Models/Lambertian_Reflection)、[Epicのスクリーントレースの制約](https://dev.epicgames.com/documentation/unreal-engine/lumen-technical-details-in-unreal-engine)。コードは本プロジェクトの既存処理と独自の限定的な近傍サンプリングによる。

## グレーディングとハイライト圧縮

従来の低彩度・青い影と暖色の明部・周辺減光・グレインを弱め、光源や素材の色が見える方向へ調整する。通常のgradeと暗視・バイザーを含む12種を同じ正本から生成する。

| 設定 | 従来 | 新しい値 |
| --- | --- | --- |
| Saturation | 0.85 | 0.98 |
| Contrast | 1.08・直線 | 1.02・黒白を保持するS字 |
| ShadowTint | 0.95 / 0.99 / 1.06 | 0.99 / 1.00 / 1.015 |
| HighlightTint | 1.03 / 1.00 / 0.95 | 1.01 / 1.00 / 0.99 |
| Vignette | 0.22 | 0.08 |
| Grain | 0.025 | 0.003 |
| 周辺の色収差 | 0.45画素係数 | 0・無効 |

フレアの光芒・横線・ゴースト・レンズ汚れは、見直し前の強さへ戻す。暗視装置のセンサーを表す専用グレインと、被弾・出血等の演出設定は維持する。

`iem_tonemap.glsl` は本プロジェクト独自のソフトショルダーとsRGB変換を持つ。サーバー光の倍率・色と間接光は、表示色へ直接掛けずsRGB変換後の近似線形光量で合成し、手動Exposure=1.0を掛ける。RGBの最大成分が0.7以下ならトーンカーブは恒等。超えると指数型の肩で1へ漸近させ、RGBを同率で縮小する。入力のピークが1を超える強い色光は徐々に白へ寄せる。暗部と中間調へトーンカーブの減光をかけず、成分別クリップによる強い色光の黄・シアン等への変色を抑える。直線コントラストも廃止し、出力0と1を保つS字にする。

`ToneMapConfig` の Exposure=1.0、ShoulderStart=0.7、HighlightDesaturation=0.12、ToneMapStrength=1.0が初期値。ToneMapStrength=0でハイライト圧縮を無効化できる。自動露出による室内外の明るさの追従は加えない。

対象クライアントのメイン描画先はRGBA8_UNORMで、入力はすでに描画されたSDR画像。元の画面でクリップ済みの情報は復元できない。圧縮できるのは、この段で加算・増幅するシーン光の浮動小数点値を含む範囲。レンズの光はシーンのトーン圧縮後、従来の表示空間で加算し、フレアの強さを肩で抑えない。シーン全体をHDR描画するAgX/ACESやCyclesのカラーマネジメントと同じ実装ではない。暗視やEMPを含む実機で最終的な強さを比較する。

`tools/check_tonemap.py` は実際のGLSLをGPUへ渡し、8192点の高輝度ランプ、暗部・中間調の恒等性、出力の単調性と範囲、sRGB往復、色の順序、黒潰れを増やさないコントラスト、圧縮の無効化を検証する。実行例: `uv run --with moderngl --with numpy python tools/check_tonemap.py`（ヘッドレスGL/EGLが必要）。通常のVulkan向け164組コンパイルとframe/gradeのリンクも確認する。

生成した部屋を実際の旧・新gradeフラグメントで描き、有限な出力と空・手の間接光除外を確認した。比較画像は検証用の生成シーン。既存のゲームキャプチャへ二重にグレーディングして比較した画像ではない。RTX 3060の同場面では、この色調改良によるgrade段の増分は約0.04msだった。ゲーム全体の実測値ではない。

守色とハイライトの扱いの参考: [Khronos PBR Neutralの説明](https://github.com/KhronosGroup/ToneMapping/blob/main/PBR_Neutral/README.md)。ここでは同実装の黒レベル補正やコードをコピーせず、SDR入力に合わせた独自の曲線を使う。

## 昼の白浮きと間接光の負荷への対応

日なたが白っぽく浮くという実機報告に対し、描画済みの表示色へ光の倍率を直接掛けていた経路を修正した。例えば表示色0.5へ1.25倍を掛けると、旧処理は0.625になる。一方、sRGBから光量へ戻して1.25倍した結果は約0.554。旧処理は光量に対して過剰な増幅になり、明るい面を圧縮領域へ押し上げやすかった。

太陽のもやも旧表示空間で調整された小さな散乱寄与を光量へ変換して加える。濃度0.004→0.0015、強さ0.8→0.5、上限0.35→0.08とし、暗い素材に白い膜が乗るのを抑える。これは限定的なもやの近似で、厳密な大気散乱モデルではない。実機で見えた問題が全て解消したという確認は別途必要。

ブルームとレンズフレアの設定は、光の見直し前のFLARE_CONFIGへ完全に戻す。トーン圧縮後に表示空間で加算するため、今回の肩によるフレアの減衰も避ける。彩度やグレイン等の新しい色調設定は維持する。

indirect単独で約7msという実機報告を受け、専用ターゲットを960×540→480×270（画素数1/4）、6→4標本へ変更。候補の深度1回で距離と受光面の向きを先に判定し、寄与しない候補の法線復元5読込を省く。光の強さは標本数で正規化し、反射光の上限・空と手の除外・深度を使う拡大は維持する。解像度と標本数の低下により、小さい形状や細かな反射の精度は下がる。

同じ単純な生成場面・同じRTX 3060で、旧0.188ms→新0.032ms。以前の0.2〜0.3msという検証値もそのような単純な場面の値で、実機の約7msを代表しない。低性能環境の実時間が同じ比率で短くなる保証はない。実機で再計測する。

`tools/check_grade.py` は実際のgradeフラグメントと有効な光格子を使い、1.25倍と0.68倍が光量として反映されること、もやの寄与が試験範囲内に収まること、レンズの表示空間加算が保持されることをGPUで確認する。例: `uv run --with moderngl --with numpy python tools/check_grade.py <vanilla-include>`。Vulkanのコンパイル・リンク、トーンカーブのGPUテストも併用する。

## 日なた・日陰が平坦に見える場合の面応答

露出の増加は採用せず、Exposureは1.0のままとする。旧 `light.fsh` は日光の入射cosが0.3を超えると `smoothstep(-0.05,0.3,cos)` が1となり、それ以上の面の向きの差が失われていた。さらに太陽が届く空気の前では、背面も含めて固定の面明暗を同じ割合で戻していた。

新 `iem_lighting_response.glsl` では、日光は `max(dot(normal,sun),0)` で連続的に変え、空・反射光は上側1.15、横1.025、下側0.90の穏やかな半球応答で向きを付ける。いずれも既存の光量への乗算なので、光のない場所を発光させない。固定の面明暗を戻す割合も日光の受光角へ連動させ、かすめる面・背面を一律に平坦化しない。

格子は総光量・日光の可視性・支配的な光の種類を持つが、実際の直達光の割合は送られていない。そのため、日なたの直達成分を最大66%とする既存の空・太陽の釣り合いに基づく近似を使う。種類が「空」でも日光の可視性が立つセルは直達光を残す。暖色・寒色の光源ブロックが支配するセルの明るさと面明暗は、この追加の空・太陽応答では変更しない。遠景も同じ連続的な入射角を使う。

`tools/check_lighting_response.py` はGPUで、旧cos=0.3以降の明るさの頭打ちがないこと、日陰の上・横・下の差、エネルギー範囲、光源ブロックだけの応答の維持を検証する。実際の `light.fsh` でも、既知の総光量・日光可視性・光の種類の格子を入力し、太陽の角度、空種別でも太陽が見えるセル、日陰、光源ブロックの経路を確認した。

追加の深度サンプル・レイ・画面処理段はない。indirectは480×270・4標本のまま。これは面の向きの陰影を改善する調整で、広い平面の内部での光の濃淡、画面外の多段反射、素材の鏡面反射を解決するものではない。実マップでの見え方は別途確認する。

## 屋外の光の配分と地図色の反射率

時刻変更で影が変化し、light/light_gridの描画も確認されたため、影判定の故障とは断定せず、光の配分を調整した。通常の昼の直達光SUNを0.55→0.85へ、晴れた開けた場所の空の係数を0.55→0.38へ変更する。空の光レベル12以下は従来の係数0.55を保ち、12〜15で滑らかに屋外側へ移す。夜（太陽の強さ0）は空の係数を変えず、雨などで太陽が弱い時も従来の空のフィルを多く残す。Exposureは1.0を維持する。

反射に使う地図色のRGBは、表示用の値からsRGBの変換で線形化して明るさを求める。中間の灰色128は、旧約0.502から約0.216となる。地図色をそのまま光量の反射率に使い、反射を強く見積もっていた点を抑える。反射率の範囲は0.02〜0.85。地図色は素材の代用であり、パックのテクスチャ平均やPBR材質から測定した反射率ではない。直達のブロック光は維持するが、室内・夜でも壁からの反射量はこの変換の影響を受ける。

シェーダー側の直達成分の近似を66%へ、遠景の日なた/日陰の倍率を1.4/0.52へ合わせる。光のデータ形式、8段階の詰め方、送信方式、レイ数は変えない。プラグインとパックを合わせて更新する。indirectは480×270・4標本のまま。

`SunLightBalanceTest` は線形化、黒白の反射率範囲、室内と夜の空の係数、晴天/雨天のフィル、実際の壁の場面での圧縮後のコントラストと影の階調余裕を確認する。単純な壁の場面では、屋外の日なた/日陰の倍率比が約1.95→3.81となり、影の値も最暗段階に張り付かない。空光5・10の同場面は従来の明るさの段階を保持する。これは計算上の比較で、提示された実マップの再レンダリングではない。実機での見え方は別途確認する。


## 旧光の筋との比較に基づく表面色の分離（実機評価待ち）

旧shaftsは320×180で視線上の日照を3〜10標本調べ、太陽色を表示色へ加算していた。拡大は深度を考慮しない4点のぼかしで、遮蔽物の境界に光が混ざる要因があった。旧画面が良く見えるという報告から、加算による色の分離を表面照明で試す。旧画像には他の設定差もあり、光の筋だけが改善要因だったと確定したものではない。

新iemDaylightTintは昼の日陰を-0.65、正対する日なたを最低+0.6へ分ける（旧は-0.3と最低+0.1）。日照可視性・面の入射角・太陽強度で連続補間し、夜は旧の-0.3へ戻す。近景・遠景で共通の関数を使い、光源ブロックの色係数は維持する。色は既存の深度を考慮した拡大と、輝度で正規化した色の乗算へ渡す。光量・露出・フレア・もや・パス数・標本数は変更しない。

これは画作りの調整で、空気中の光の柱や視線方向の散乱を再現しない。既存の粗い格子や低解像度の面照明の制約も残る。新しい光の加算・ぼかしを導入しないことと、すべての光漏れが解消されることは別である。

GPUテストで日なた/日陰の色の分離、夜の復帰、日照の連続補間、灰色面の輝度維持、黒の維持を確認する。画面の見栄えは実マップで旧版と比較する必要があり、採用判断は未完了。


## 接地の遮蔽と反射光の判定の分離（2026-10-30、実機評価待ち）

indirectの接地遮蔽を、反射光の2点経路確認より前で集計する。従来は途中に別の物があると反射光だけでなく遮蔽物の寄与も取り消していた。候補の距離、受光側の法線、相手の法線復元による細い輪郭の除外は維持する。反射光の経路確認は維持し、BounceStrengthが0の場合はその確認を省く。

4標本の位置を半径の60%から35%へ寄せ、接地付近を拾いやすくする。同じ標本を使う反射光の分布も変化する。ContactStrengthに掛ける補助係数を1.5とし、局所的な減光の上限を15%から28%へ変更する。480×270、4標本、半径1.25m、12〜24mの距離フェードは維持する。GPUの実時間は未計測で、近い候補が増えると反射光の経路確認まで進む画素が増える可能性がある。

これは画面内の接地補助で、環境光と直達光を分離したAOではない。現在は合成済みの表面光を減衰させるため、接地付近では直達光にも影響する。平らで遮蔽物のない面には減光しない。画面外・物の裏側の遮蔽は推定できず、トラック全体の下の広い暗がりを保証しない。

`tools/check_indirect.py <vanilla-include>` は実際のindirectフラグメントを生成した深度で描画し、近接部分、開けた平面、半径より離れた前景、空、手、遠景、反射光無効時の遮蔽維持と出力上限を確認する。平面より0.6m手前に置いた面の試験では最小可視率0.9431。実マップの見栄えは未確認。
