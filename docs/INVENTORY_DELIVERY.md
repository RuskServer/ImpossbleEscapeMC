# コスト上限と素材納品

通常の受け取りは、アイテムを入れる前に収納コストを確かめる。空きスロットが見えていても、新しいスタックのコストが入らなければ取らない。既存スタックへ入る分は追加できる。漁り・通常拾得/リグ移動・トレーダー購入・マーケット受け取りは共通のコスト判定を使う。

漁りで取れない分は死体・コンテナに残し、拾えない地面のアイテムも元の場所に残す。バックパック表示中のホットバーへの受け取りでは、表示で隠れている本物の持ち物のコストも差し引く。地図欄・閉じたリグ欄には入れない。購入の入りきらない分は既存の返金処理へ渡す。マーケットは一部だけ受け取って出品を残すことがないよう、一括受け取りが可能な時だけ反映する。

ロビーでも、新規持ち込みで収納コストが増えて上限を超える操作を止める。すでに超過している荷物を整理して減らす操作は可能。占有表示の更新がアイテムを自動で削除・地面へ排出する処理は廃止した。予期しないリグ変更で閉じた欄の物も、入りきらない分は元の欄に残す。ロビーの装備準備用の表示と出撃時の容量検査は維持する。管理用の直接付与や、自分の装備・カーソルの返却を通常の新規取得へ一律に変えるものではない。

隠れ家の強化・製作素材とトレーダーの交換素材はMaterialDeliveryを共用し、クエスト納品と同じHandInPlacesを探索・保存に使う。順番は持ち物、持ち物内のバッグ、オフハンドのバッグ、スタッシュの各ページとそのバッグ。装備そのものや中身入りバッグ本体を消費せず、バッグの入れ子には再帰しない。素材の個数を表示する時と消費する時の対象をそろえる。支給品を除外し、クエスト固有のFIR・種類・口径・クラス条件は既存の判定を維持する。

隠れ家・交換素材は必要数をすべて確保できるか計画し、不足なら一切減らさない。実体を読み直したうえでコピー上で消費し、変更するバッグとスタッシュをすべて直列化してから持ち物へ反映する。保存エラー時に他の素材だけ減らすことはしない。開いているバッグは未保存の実体を読み、納品後は実体とPDCの両方を更新する。旧STRING形式も読める。納品の際は保存済みの容量外スロットを切り捨てず、読めないバッグは候補にしない。

交換品・製作完成品・製作取り消しの返却は、持ち物とスタッシュへ全部入る場合だけ反映する。入らなければ地面へ落とさず、交換は元の素材・状態・代金を戻し、購入制限を進めない。完成品はキューに残し、素材の返却先がない製作取り消しもキューを残す。隠れ家建築の失敗時は、生成した代用品ではなく元の場所とメタデータを含む素材状態を復元する。

これはメインスレッド内での操作の整合性であり、DB・プレイヤーファイル・ワールドを横断したクラッシュ時の一括トランザクションを追加するものではない。永続化は既存のPlayerDataModuleの順序付き非同期保存を使用する。

検証: CostInsertionTest、CostTransferTest、MaterialDeliveryTest、HandInStoreTest、CostLayoutTest、TraderBarterTest、CraftQueuesTest。実転送関数への拒否・部分挿入・元スタック保持・許可スロットの検証と、実際の納品Storeに保存失敗を注入して元の持ち物・ページが変わらないことの検証を含む。バッグの開閉・スタッシュへの保存・実GUIでの納品と満杯時の受け取りは実サーバー確認待ち。
