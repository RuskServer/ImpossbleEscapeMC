# SCAV死体の短時間ラグドール

SCAVの死亡直後に、部位別のItemDisplayを短時間だけ物理更新し、落ち着いた姿勢で固定する。プレイヤーの死体は現在のMannequin表示を使い続ける。

## 表示と死体漁り

中身の所有者は既存のMannequin。`CorpseManager` で装備・予備弾を保存した後の `CorpseCreatedEvent` を受け、SCAV死亡として記録されている個体だけ表示を置き換える。プレイヤーの死亡処理・ドッグタグ・中身の転送処理は変更しない。

- 頭・胴・左右の腕・左右の脚の6部位をItemDisplayで描画する。
- 元の死体と死亡エンティティをプレイヤーから隠し、頭・胴・手足に追従する11個のInteractionを操作判定にする（頭1、他の5部位は各2）。
- Interactionの右クリックは既存の `SearchGUI.open(player, mannequin)` へ渡す。同じ死体の実インベントリを共有し、既存の検索・FIR・部分取得・バックパック・GUI保護を通す。
- 取得後の `CorpseAppearanceEvent` で装備表示を更新する。各装備のスロットが空になれば表示も消す。
- SCAV死体の0〜5番は装備専用として空きも維持する。予備弾・追加ルート品は `CorpseLootLayout` で6番以降だけへ詰め、容量超過分は地面に落とす。空き防具欄へ弾を入れると未対応防具と誤判定するため、汎用 `Inventory.addItem()` で全欄を埋めない。

固定スキンはパックの `minecraft:entity/player/wide/scav` を参照する。通常生成SCAVのSlick・Trooperは既存の防具テクスチャから作る部位モデル、MF-UNTARは既存の3Dアイテムモデルを使う。ヘルメットと手持ちは実際のItemStackを表示するため、CustomModelDataなども引き継ぐ。

現在は脚・足の装備、上記以外の胸装備がある場合、装備を表示から省く代わりに通常のMannequin死体を使う。装備の厚み全体を正確に物理衝突へ取り込むものではなく、ヘルメット・銃の位置や地面との隙間は実ゲームでの確認対象とする。

## 物理

`RagdollPhysics` はBukkitに依存しない位置ベースの関節計算。胸・腰・肩・股関節を距離拘束で保ち、頭・手先・足先を接続する。首・腕・脚には可動角の制限があり、肢体が胴から離れないようにする。Minecraftの腕・脚モデルと同じく、それぞれ1本の部位として扱う。肘・膝を持つ人体全身の剛体シミュレーターではない。

被弾時に射手から被害者への向き（通常の飛び道具なら速度方向）を記録し、直近100tickの情報を死亡時に使う。移動速度と小さな個体差を加え、上体に先に力を与えて手足へ遅れて伝える。古い被弾や環境死では向きの代替値を使う。弾の完全な3次元衝突点・エネルギーを再現する処理ではない。

1更新を4小ステップに分け、重力・速度上限・関節拘束・接触を解く。`RagdollTerrain` がロード済みブロックのVoxelShapeを世界座標へ変換し、点・部位途中に加え、回転した部位箱全体とブロック箱を15分離軸で判定する。角が壁の中へ入らないまま面が交差する薄壁も検出し、最小の押し戻しで分離する。部位箱にはスキンの外層を含む0.01ブロックの余裕を加える。各小ステップの最後は、全身の最大押し戻し量が0.00025ブロック未満になるまで、上限16回で接触を再確認する。接触が早く収まればその時点で打ち切る。通常ブロックを斜めに並べた壁の凹凸では、後から動いた腕・脚が肩の軸を回して頭や胴を再侵入させるため、固定4回では残った接触も収束させる。半ブロックや階段の形状も入力に使う。衝突形状は物理更新内だけキャッシュする。液体の浮力、死体同士の押し合い、全身の厳密な自己衝突は扱わない。

接地して小さな動きが続けばスリープし、それ以後の物理更新を止める。初期値では最大48物理更新（毎tick進められれば約2.4秒）でその姿勢に固定する。静止後に床が壊れても再び落下させる仕組みではない。高所・強い負荷・未読込境界の挙動は実ワールドで確認する。

## 負荷と寿命

```yaml
scav-ragdoll:
  enabled: true
  debug: false
  max-active: 6
  max-corpses: 64
  max-animation-ticks: 48
  millis-per-tick: 3
```

- 同時に物理更新する死体、表示死体の総数に上限を設ける。上限に達した新しい死体は通常のMannequinで生成し、中身を失わせない。
- 物理はサーバースレッド上で順番を回し、1tickの時間予算を超えたら次tickへ繰り越す。1体の更新途中を中断する厳密な時間上限ではない。負荷時はアニメーションの実時間が長くなる。
- 未読込チャンクは壁として扱い、物理のために同期ロード・生成しない。無効な計算や長時間の処理未完了は通常死体へ戻す。
- 1体あたり基本6表示＋1操作エンティティと、隠れた既存Mannequin。装備で最大6表示が加わる。装備更新時に古い装備表示を残さない。
- レイドの死体清掃、元Mannequinの削除、関連チャンク・ワールドのアンロードで、操作判定と表示も削除する。死亡地点とすべての操作判定のチャンクを確認する。元の死体と同じく永続保存を目的としない。
- プラグイン停止時はタスクと追加エンティティを片付け、まだ有効なMannequinは通常表示へ戻す。既存の最終的な死体清掃は維持する。

## リソースパック

`New_IEM_Resorcepack/tools/scav_ragdoll.py` が13組のアイテム定義・部位モデル、計26JSONと `assets/minecraft/atlases/items.json` の登録を生成する。既存のスキン・防具テクスチャ・MF-UNTARモデルを参照し、新しい画像や既存シェーダーの変更は追加しない。プラグインとこのモデルを含むパックを合わせて更新する。生成元はパックの `IEM_SCAV_RAGDOLL_CREDITS.txt` に記載する。

エンティティ用画像はアイテムの自動収集対象外なので、itemsアトラスに `iem:corpse/scav` と `iem:corpse/armor/{iron,diamond}` の別名で登録する。部位モデルはこのsprite名を参照する。画像の存在だけでなく、モデル→itemsアトラス→既存PNGの解決を確認する。[1.21.11公式更新内容](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-11) にアイテム用アトラスの分離が記載されている。手持ち装備は腕の回転へX -90度、続いてローカルY 180度の補正を合成する。銃データパックや銃モデル自体は変更しない。

ItemDisplayの変換補間は [Paper公式資料](https://docs.papermc.io/paper/dev/display-entities/) を参照。モデルの任意角回転は対象クライアントで使える形式で、[1.21.6公式更新内容](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-6) にも回転角制限の緩和が記載されている。

起動時に `SCAV ragdoll enabled` を記録する。`scav-ragdoll.debug: true` で起動すると、死亡マーカー不足・人数上限・未対応装備による見送りと表示生成をサーバーログへ出す。表示されない場合はこの入口判定と、更新したjarが実際に読み込まれているかを確認する。変更は新しく生成する死体が対象で、既存死体を後から変換しない。

## 検証と実機確認

`CorpseLootLayoutTest` は、予備弾が装備欄へ入りラグドール対象から外れる旧挙動を再現し、修正後の対象判定、装備欄の維持、スタックの分割・結合、入力の保持、容量超過を含む弾数保存を検証する。

`RagdollPhysicsTest` は複数の向きと乱数種で、落下・関節長・床より上の体と表示箱の角・静止、壁・半ブロック、力の方向、遠い座標・負の高さを確認する。部位モデルの参照・UV・JSON構造も確認する。`RagdollCollisionTest` は角だけでは拾えない薄壁との面交差と、回転箱の分離軸を検証する。`RagdollWallTest` は3種類の壁厚、壁の角の有無、7方向、8乱数種の336条件で、60tickの各表示姿勢の角が壁・床へ入らないことと関節の接続を確認する。旧実装で壁への侵入を再現してから検証する。`RagdollDiagonalWallTest` は通常ブロックを斜めに並べた壁・通路、3種類の傾き、4方向、複数の向きと乱数種を361条件で検証する。旧実装で10tick目に頭が約9mm壁へ入る配置を先頭に置き、全フレームと標準48tickで停止した姿勢を部位箱全体のSATで確認する。銃やヘルメットの形状全体を衝突に使う変更ではなく、これらの装備とクライアントの表示補間は引き続き実機で確認する。

Java計算から生成した軌跡のGIFは作業用プレビューであり、Minecraft内のキャプチャではない。

実ゲームでは次を確認する。

1. SCAVの死亡方向、元エンティティとの二重表示、ヘルメット・アーマー・銃の位置。
2. 動作中・静止後に漁れること、2人同時の取得、部分取得、装備を取ると表示が消えること。
3. 壁際・階段・段差・高所・水辺・チャンク境界。特に薄い衝突形状と装備の接地。
4. 同時死亡の上限、時間予算、チャンクアンロード、レイドの清掃、停止時に表示や操作判定が残らないこと。
5. プレイヤー死体と未対応装備の通常死体が維持されること。

## 将来のプレイヤー対応

表示と中身を分けた構造は再利用できるが、このモデルは固定SCAVスキンを部位別UVで読む。任意のプレイヤースキンURLを、そのままこのItemDisplayの部位テクスチャへ指定できる構造にはしていない。プレイヤー用には、動的なスキンの取り込み・部位モデル／テクスチャの配布、または別の描画方法が必要になる。スキン取得・配布を主スレッドの死亡イベント内で行う設計にはしない。


## 死体右クリックの補助判定（2026-10-30）

レイド中、胴体に近づいても無反応という報告への対応。元のInteractionイベントが届かない原因は実機で未確定。通常のイベント経路を残し、右クリックの空・ブロックイベントから表示部位の回転箱へ視線を飛ばす補助経路を追加した。各部位の物理姿勢を使い、装備モデルは判定に含めない。補間表示と物理姿勢はアニメーション中に短い差がある。

距離はプレイヤーのENTITY_INTERACTION_RANGE属性を使用し、同じワールドの有効な死体のうち最も近い交差を選ぶ。ブロックに先に当たる場合・観戦者・オフハンドは対象外。空や地面への元の操作が拒否されていても、その拒否は解除せず、死体のInteractionを対象とするPlayerInteractAtEntityEventを別途発火する。補助経路では全優先度のハンドラーが完了してからキャンセルを確認し、許可された場合だけ既存SearchGUIを開く。空・ブロック操作のみを制限する外部プラグインは、そのルールが自動的にエンティティ操作へ引き継がれるわけではない。死体の利用可否はエンティティ操作イベントで設定する。

既存の同一死体GUIの二重オープン防止と、Mannequinが持つ共有インベントリ・保存処理を利用する。データパック・パックの変更はない。debug=trueでは補助経路への到達、操作キャンセル、死体無効/距離、GUIが開いたかを出力する。プレイヤー名や座標はログへ追加しない。

RagdollPickingTestは回転した部位、射程外、逆向き、平行な視線、箱内部、負の高さ・大きい座標を確認する。保護プラグインとの実機統合、レイドでの無反応解消は更新jarでの確認が必要。


## 部位別の操作判定（2026-10-31）

胴体の固定箱1個だけに依存しない。頭1個、胴・左右の腕・左右の脚に各2個、計11個のInteractionを各姿勢へ追従させる。Interactionは回転できないため、長い部位を2分割し、それぞれを覆うワールド軸の箱にする。通常クリックは操作箱で受けた位置を実際の回転部位へ投影し、部位への距離・遮蔽を検証する。空・ブロックからの補助経路では回転部位箱への視線交差を使う。スキン外層を含む余裕は各軸0.025ブロック。

エンティティの通常クリックはネイティブの接触位置を使い、補助経路だけ現在の視線で対象を選ぶ。どちらもENTITY_INTERACTION_RANGEとブロック遮蔽を検証する。ブロックが先にある場合は原則拒否し、接触誤差のみ視線方向に0.02ブロックまで許容する。壁の厚みを無視したり、見えていない部位を距離だけで開く処理は入れない。補助イベントの対象も、狙った部位を覆うInteractionにする。

エンティティ操作をMONITORで受け、GUIは翌tickに開く。元イベントはこのモジュールでキャンセルせず、全ハンドラーの後でもキャンセルされていない要求があることを確認する。同じプレイヤー・同じ死体のINTERACT/INTERACT_ATや補助経路は1回にまとめる。翌tickにもプレイヤーのオンライン状態、死体の同一性、射程と遮蔽を再確認する。元の空・ブロック操作の拒否を解除しない。検索・中身保存・取得処理は既存SearchGUIをそのまま使う。

操作箱が単独で消えた場合は死体全体を消さず、20tickごとの確認で欠けた箱だけ復旧する。物理更新中は各renderでも確認する。通常死体へのフォールバック、死体削除、チャンク/ワールドのアンロード、プラグイン停止で全操作箱を回収する。物理・地形衝突・見た目のアニメーションは変更しない。操作エンティティ数は従来の1個から11個へ増える。表示補間中の姿勢差と、保護プラグインを含めた実機での操作感・負荷は確認対象。

`RagdollInteractionGeometryTest`は200回転で全身の外層が操作箱に入ること、従来の内側箱では拾えない外層のクリック、接触許容差、壁・薄い障害物・射程外の拒否を検証する。`RagdollHandleLifecycleTest`は実Actorを使い、11個の生成・再利用・部位に合う合成イベント対象の選択・部分欠損の復旧・全回収を確認する。これらは実クライアントのパケット配送や外部プラグインの挙動を再現するものではない。


## 受信したクリック位置の保持（2026-10-31）

11個のネイティブInteractionでクリックを受信できても、従来は内側の回転箱へカメラの視線を引き直していた。外接する操作箱の隅には当たるが内側の回転箱には当たらないケースと、GUIを開く翌tickまでに視線が変わるケースをテストで再現した。通常クリックにはこの完全一致を要求しない。

PlayerInteractAtEntityEventの実際の接触位置を、クリックされた部位のローカル座標へ保存する。通常のPlayerInteractEntityEventで接触位置が無い場合は、クリックされた操作箱のプレイヤーに最も近い点を使う。対象が実際にその死体へ割り当てた有効な操作箱であることを確認し、通信中の移動を考慮してイベントの接触点に0.35ブロックの余裕を設ける。その点を本来の部位箱へ投影する。クリック用の外周余白を遮蔽確認点へ持ち込まず、確認点が床・壁へはみ出すことを避ける。

GUIを開く直前も、保存した点を現在の部位姿勢へ戻して使う。カメラを同じ向きに固定し続ける必要はない。現在の部位の操作箱までの距離（操作射程＋0.05ブロック）、実際の部位点までのブロック遮蔽、イベントの最終キャンセル、プレイヤーと死体の有効性は再確認する。ブロックの接触許容差0.02ブロックは維持する。壁越しのGUI強制オープンやキャンセル解除は行わない。同じイベントが複数のハンドラーへ配送されても1要求にまとめる。

`/scavspawn corpsecheck`（OP・プレイヤー専用）は、最終クリックの処理結果と経過秒、8ブロック以内のラグドール死体の有効な操作箱数・本人への表示許可・中身データの有無・操作射程・現在の視線の交差を表示する。イベント登録プラグイン名も表示するが、これはキャンセル元を断定するものではない。診断は設定変更や再起動なしで実行でき、拒否を解除しない。クリックの診断記録は退出・停止時に破棄する。通常Mannequin表示やプレイヤー死体はこのラグドールの追跡対象ではない。

RagdollLootTargetTestは従来のネイティブ外接箱の隅と翌tickの視線変更での誤拒否を再現し、保存位置の保持・部位への追従・床に確認点を入れないこと・壁・距離・不正入力を確認する。RagdollHandleLifecycleTestでは実ActorとPlayerInteractAtEntityEventから位置を取り出し、実際の検証メソッドで視線変更後の許可、壁・射程外の拒否を確認する。実クライアントのパケット配送や外部プラグインを通す実機確認は引き続き必要。無反応が残る時は、その死体をクリックした直後にcorpsecheckを使い、受信なし・イベントキャンセル・射程／遮蔽・中身データ／GUI拒否を区別する。
