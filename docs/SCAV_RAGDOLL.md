# SCAV死体の短時間ラグドール

SCAVの死亡直後に、部位別のItemDisplayを短時間だけ物理更新し、落ち着いた姿勢で固定する。プレイヤーの死体は現在のMannequin表示を使い続ける。

## 表示と死体漁り

中身の所有者は既存のMannequin。`CorpseManager` で装備・予備弾を保存した後の `CorpseCreatedEvent` を受け、SCAV死亡として記録されている個体だけ表示を置き換える。プレイヤーの死亡処理・ドッグタグ・中身の転送処理は変更しない。

- 頭・胴・左右の腕・左右の脚の6部位をItemDisplayで描画する。
- 元の死体と死亡エンティティをプレイヤーから隠し、胴に追従するInteractionを操作判定にする。
- Interactionの右クリックは既存の `SearchGUI.open(player, mannequin)` へ渡す。同じ死体の実インベントリを共有し、既存の検索・FIR・部分取得・バックパック・GUI保護を通す。
- 取得後の `CorpseAppearanceEvent` で装備表示を更新する。各装備のスロットが空になれば表示も消す。

固定スキンはパックの `minecraft:entity/player/wide/scav` を参照する。通常生成SCAVのSlick・Trooperは既存の防具テクスチャから作る部位モデル、MF-UNTARは既存の3Dアイテムモデルを使う。ヘルメットと手持ちは実際のItemStackを表示するため、CustomModelDataなども引き継ぐ。

現在は脚・足の装備、上記以外の胸装備がある場合、装備を表示から省く代わりに通常のMannequin死体を使う。装備の厚み全体を正確に物理衝突へ取り込むものではなく、ヘルメット・銃の位置や地面との隙間は実ゲームでの確認対象とする。

## 物理

`RagdollPhysics` はBukkitに依存しない位置ベースの関節計算。胸・腰・肩・股関節を距離拘束で保ち、頭・手先・足先を接続する。首・腕・脚には可動角の制限があり、肢体が胴から離れないようにする。Minecraftの腕・脚モデルと同じく、それぞれ1本の部位として扱う。肘・膝を持つ人体全身の剛体シミュレーターではない。

被弾時に射手から被害者への向き（通常の飛び道具なら速度方向）を記録し、直近100tickの情報を死亡時に使う。移動速度と小さな個体差を加え、上体に先に力を与えて手足へ遅れて伝える。古い被弾や環境死では向きの代替値を使う。弾の完全な3次元衝突点・エネルギーを再現する処理ではない。

1更新を4小ステップに分け、重力・速度上限・関節拘束・接触を解く。`RagdollTerrain` がロード済みブロックのVoxelShapeを世界座標へ変換し、点・部位途中・回転した表示箱の角で接触を確認する。半ブロックや階段の形状も入力に使う。衝突形状は物理更新内だけキャッシュする。液体の浮力、死体同士の押し合い、全身の厳密な自己衝突は扱わない。

接地して小さな動きが続けばスリープし、それ以後の物理更新を止める。初期値では最大48物理更新（毎tick進められれば約2.4秒）でその姿勢に固定する。静止後に床が壊れても再び落下させる仕組みではない。高所・強い負荷・未読込境界の挙動は実ワールドで確認する。

## 負荷と寿命

```yaml
scav-ragdoll:
  enabled: true
  max-active: 6
  max-corpses: 64
  max-animation-ticks: 48
  millis-per-tick: 3
```

- 同時に物理更新する死体、表示死体の総数に上限を設ける。上限に達した新しい死体は通常のMannequinで生成し、中身を失わせない。
- 物理はサーバースレッド上で順番を回し、1tickの時間予算を超えたら次tickへ繰り越す。1体の更新途中を中断する厳密な時間上限ではない。負荷時はアニメーションの実時間が長くなる。
- 未読込チャンクは壁として扱い、物理のために同期ロード・生成しない。無効な計算や長時間の処理未完了は通常死体へ戻す。
- 1体あたり基本6表示＋1操作エンティティと、隠れた既存Mannequin。装備で最大6表示が加わる。装備更新時に古い装備表示を残さない。
- レイドの死体清掃、元Mannequinの削除、関連チャンク・ワールドのアンロードで、操作判定と表示も削除する。死亡地点と操作判定のチャンクを確認する。元の死体と同じく永続保存を目的としない。
- プラグイン停止時はタスクと追加エンティティを片付け、まだ有効なMannequinは通常表示へ戻す。既存の最終的な死体清掃は維持する。

## リソースパック

`New_IEM_Resorcepack/tools/scav_ragdoll.py` が13組のアイテム定義・部位モデル、計26JSONを生成する。既存のスキン・防具テクスチャ・MF-UNTARモデルを参照し、新しい画像や既存シェーダーの変更は追加しない。プラグインとこのモデルを含むパックを合わせて更新する。生成元はパックの `IEM_SCAV_RAGDOLL_CREDITS.txt` に記載する。

ItemDisplayの変換補間は [Paper公式資料](https://docs.papermc.io/paper/dev/display-entities/) を参照。モデルの任意角回転は対象クライアントで使える形式で、[1.21.6公式更新内容](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-6) にも回転角制限の緩和が記載されている。

## 検証と実機確認

`RagdollPhysicsTest` は複数の向きと乱数種で、落下・関節長・床より上の体と表示箱の角・静止、壁・半ブロック、力の方向、遠い座標・負の高さを確認する。部位モデルの参照・UV・JSON構造も確認する。Java計算から生成した軌跡のGIFは作業用プレビューであり、Minecraft内のキャプチャではない。

実ゲームでは次を確認する。

1. SCAVの死亡方向、元エンティティとの二重表示、ヘルメット・アーマー・銃の位置。
2. 動作中・静止後に漁れること、2人同時の取得、部分取得、装備を取ると表示が消えること。
3. 壁際・階段・段差・高所・水辺・チャンク境界。特に薄い衝突形状と装備の接地。
4. 同時死亡の上限、時間予算、チャンクアンロード、レイドの清掃、停止時に表示や操作判定が残らないこと。
5. プレイヤー死体と未対応装備の通常死体が維持されること。

## 将来のプレイヤー対応

表示と中身を分けた構造は再利用できるが、このモデルは固定SCAVスキンを部位別UVで読む。任意のプレイヤースキンURLを、そのままこのItemDisplayの部位テクスチャへ指定できる構造にはしていない。プレイヤー用には、動的なスキンの取り込み・部位モデル／テクスチャの配布、または別の描画方法が必要になる。スキン取得・配布を主スレッドの死亡イベント内で行う設計にはしない。
