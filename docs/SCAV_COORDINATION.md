# SCAV救援・観測共有・捜索分担

## 救援優先度

呼び出し側の体力低下、制圧度、直近2秒の被弾・視認、援護人数、救援者との距離を評価する。
既存の救援先が有効なら最低2秒担当し、優先度が20を超えて上がった時だけ切り替える。
別の交戦への転属は転属先の累計枠を消費し、元の交戦の枠は返さない。
同じ交戦内の呼び出し元変更・同じ救援者の更新は追加枠を消費しない。
交戦中の個体を救援へ引き抜かず、従来の声の範囲・遮蔽による距離制限も維持する。
優先度比較は要請を受けた時に行う。全SCAVへ一括送信する仕組みではない。

## 観測情報

直接視認した位置・水平速度・対象ID・観測者ID・観測tickをコピーして伝える。
敵エンティティを共有しない。報告から実際の最新座標を読み出す処理はない。
報告の有効期間は10秒、推定の誤差は経過時間で増え、速度による先読みは最大1秒・6ブロック。
この共有情報は移動・照準に使用し、targetやlastKnownLocationには設定しない。
共有だけでは射撃・制圧射撃を開始しない。独力で見た・聞いた敵への既存処理はそのまま。
今回の共有対象は視認報告。音の情報を再伝達する仕組みは追加していない。

新しい報告が届いている間は呼び出し側の後方左右から援護する。
2体の救援者には交戦内で左右別の位置を割り当てる。
視認報告が3秒以上古くなったら捜索へ移行する。
呼び出し側が死亡・無効化されても、有効な報告の期限内だけ短い捜索を続ける。

## 捜索分担

同じ交戦・同じ対象ごとに8方向の候補地点を用意し、別々の地点を予約する。
観測した移動方向を基準に、前方・左右・後方を含む地点を選ぶ。
自分で見失った側の通常捜索にも同じ予約を使う（直後の追跡は従来どおり優先）。

候補地点はロード済みチャンク内かつ経路到達可能なものに限る。
地点予約は3秒で失効し、継続担当中は更新。接敵・転属・死亡時には解除する。
交戦の統合時は予約を解除して競合を解消し、確認済み地点の記録を統合する。

地点に近づき、最低1秒確認して視野角と遮蔽の検査を通った場合だけ「確認済み」とする。
記録は5秒で失効し、それより新しい視認報告があれば再確認できる。
これは小さな確認地点の分担で、部屋全体や壁の裏を確認済みにはしない。
経路候補の検査は捜索個体ごとに最大1秒に1回、最大8地点。

## ログ・確認

既存のAIログが有効なら以下を記録する。

- HELP_ASSIGNED：呼び出し元、前の呼び出し元、優先度、観測tick
- SEARCH_SECTOR_ASSIGNED：対象ID、観測tick、誤差、担当地点
- SEARCH_SECTOR_INSPECTED：確認した地点

ScavCoordinationTestで報告コピー・期限・先読み上限、優先度の切り替え猶予、
重複しない地点予約・失効・到達不可・再観測、左右分担、転属時の累計枠を確認する。
ScavHelpEncounterTestで既存の上限・連鎖・交戦統合・失効の挙動を確認する。

実サーバーでは遮蔽越しに救援が射撃しないこと、負傷した呼び出し元への担当変更、
2体の左右配置、見失った敵に対する別地点への捜索、行き止まりからの復帰を確認する。
