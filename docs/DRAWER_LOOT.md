# 開閉する2段ルート引き出し

`drawer_command.txt` のBlockDisplay 15部品をプラグインで再現する。素材はLIGHT_GRAY_CONCRETEで、新しいパックアセットは不要。筐体5部品は固定、上下各5部品が手前へ0.625ブロック、8tickでスライドする。

## 設置と削除

OPが対象マップのワールドで、置きたい床を5ブロック以内から見て実行する。床の上の1ブロックが空いている必要がある。取っ手は設置者側を向くよう4方向に丸める。

```text
/loot draweregg <mapId> <crateId>
/loot drawer place <mapId> <crateId>
/loot drawer list <mapId>
/loot drawer remove
```

`/loot draweregg` でマップ・クレートを記録した専用エッグを入手できる。メインハンドに持ち、ブロックの面を右クリックすると、その面の前の空き1ブロックに直接設置と同じ検証・向き・登録・初回補充で設置する。OP専用で、エッグは消費せず繰り返し使える。空中やエンティティの右クリックではバニラの動物を生成しない。

削除は対象の引き出しを見て実行する。既存 `/loot remover` の削除ツールでも右クリックで消せる。削除時にはGUIを閉じ、登録・表示部品・当たり判定・衝突用バリアを取り除き、中身はドロップしない。

## 漁りと補充

上下をそれぞれ右クリックして漁る。各段27スロットで、指定したクレートを段ごとに独立して抽選する。同じ段を複数人で見ても、全員が1つの実インベントリを使う。最後の閲覧者が閉じたときに戻り、別の人がまだ見ている段は閉じない。開閉時はバニラの樽の音を使う。

検索・取得は既存SearchGUIを共有する。検索済み欄、検索中の回転、レアリティの衝撃波・音、FIR、タスク品発見通知、バックパック優先移動、部分取得とGUI保護は同じ処理を通る。`SearchableLootSource` が新しい入力源を追加し、既存のブロックコンテナと死体の書き戻しは維持する。

レイド開始時の通常コンテナ補充、`/loot refill`、`/loot refill this` で補充する。対象を補充・削除するときは閲覧画面を先に閉じる。未読込チャンクは補充のために同期ロードせず、保存した世代番号を次の読込時に適用する。

## 保存とライフサイクル

マップJSONの `lootDrawers` にID・クレート・整数座標・向き・補充世代を保存する。古いマップでは空のリストとして扱い、既存 `lootContainers` とは独立する。

各段のInteractionに中身と検索済み欄をPDCで保存する。取得した直後に中身を書き戻し、閉じるとき・チャンクを下ろすときにも保存する。読込時は保存済みInteractionを再利用し、表示部品だけ再構築して閉じた位置に戻す。データ復元に失敗した段は勝手に再抽選せず、開けない状態にしてログに残す。

1台につき表示15エンティティ、操作用Interaction 2エンティティ、衝突用バリア1ブロックを使う。通常の破壊・ピストン・爆発による移動を防ぐ。再読込で登録位置が別のブロックになっていれば上書きせずログに残す。家具自体を消す場合は専用コマンドか削除ツールを使う。

## 検証

`DrawerModelTest` は4方向の移動・開口方向、筐体と可動部の分離、負座標・補充世代を含むマップ保存、旧マップ互換を確認する。元コマンドの15部品の寸法・位置も照合済み。ビルドおよび既存の無線・HUD・スポーン診断テストを実行した。

実ゲームでの確認は未実施。導入後は上下の開閉、同じ段を2人で開いて片方だけ閉じる操作、部分取得、開いたまま補充、チャンク再読込とサーバー再起動、削除を確認する。
