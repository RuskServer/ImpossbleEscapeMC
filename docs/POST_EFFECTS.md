# PostEffectの状態・重ね順・再生・送信

`ScreenEffectService`の公開static入口は維持し、内部を次の担当に分けている。死亡演出の新しいパック資産を含む変更では、プラグインとリソースパックを同時更新する。

| 担当 | 内容 |
| --- | --- |
| `ScreenEffectService` | イベントと定期観測、演出の時間割の組み立て、遷移に伴う音・コールバックの実行 |
| `ScreenEffectState` | プレイヤー1人の表示状態、濡れ具合と送信済み値、読み込み待ち、再生、心拍の余韻 |
| `DeathScene` | 死亡地点での待機・暗転転送・ロビー復帰。描画時計は単一シェーダーへ渡す |
| `ScreenEffectPlayback` | 演出1本の開始・待機・進行・終了・中断。Bukkitや送信処理を呼ばない |
| `PostEffectStack` | 読み取り専用の状態スナップショットから、重ねるエフェクト一覧を作る純粋関数 |
| `PostEffectTransport` | `Player.postEffects()`を操作する唯一の場所。構成の変更、強制再送、掃除 |

描画状態・再生時計・構成・送信・死亡進行の内部クラスはpackage-private。公開の効果APIやDIサービスを追加していない。マズルの1tick信号は従来の`MuzzleFlashSignal`が担当し、PostEffectの構成変更には使わない。

## 状態と寿命

サービスが持つのは`UUID → ScreenEffectState`の一つのMap。画面の層ごとにUUIDのMap/Setを別々に管理しない。全操作はメインスレッドで行い、PLAYER_LOADEDパケットの受信だけメインスレッドへ渡す。

退出・再参加では状態オブジェクトを取り除き、再生を中断し、マズル信号も解除する。死亡では戦闘用の層を外して死亡演出に置き換える。診断・読み込み用の暗転・メニューの印は従来どおり独立して保持する。バイザーを外した時の濡れ具合の解除は従来の定期観測が行う。

停止時は更新タスク、Bukkit/PacketEventsのリスナー、濡れ具合の送信チャンネルを解除し、全状態を破棄する。停止前のパケット受信から予約された処理は、同じサービスが有効な場合だけ実行する。

## 描画順と選択規則

クライアントが送られた順に描くため、次の順序を`PostEffectStack`に集約している。

1. 他の名前空間の既存エフェクト（元の順序と重複を維持）
2. 確認用control_debug
3. 空、照明弾、フラッシュライト
4. grade、またはバイザー/暗視付きgrade。画作りが無い場合はcontrol
5. まぶしさ（画作りが有効な場合のみ）
6. 負傷
7. 再生中の演出
8. 被弾
9. メニューのぼかし止め
10. 診断probe
11. 読み込み用cover

gradeとcontrolは排他的。バイザーは独立した段として足さず、対応するgradeを選ぶ。coverと演出のintro_0が同時に入る場合も、従来の重複を維持する。

同じ演出層では、後から要求された演出が再生中のものを置き換える。演出ごとの新しい重要度や待機キューは導入していない。中断された演出の残りの段・完了コールバックは実行せず、再開もしない。PDAの呼び出し元は従来どおり`isPlaying`で中断を検出する。

## 再生とコールバック

読み込み待ち中は時計を進めない。`showWhileWaiting`が有効なレイド/PDAイントロは、最初の段だけ先に表示する。待機が解除された最初のtickは開始だけを行い、そのtickで最初の段の時間を減らさない。PLAYER_LOADED後の10tickの待機、400tickの待ち上限、ShaderWarmup中の停止を維持する。読み込み完了が二重に通知されても処理は一度だけ。

再生時計は遷移結果を返す。サービスがその結果に応じて心音・段のコールバック・表示更新を行う。最初の段は表示してからコールバックを呼び、以後の段はコールバックを呼んでから表示する。コールバックが別演出への置換や状態破棄を起こしても、古い再生を復活させない。

既存の時間割は次のとおり。読み込み待ちの時間は含まない。

| 演出 | 時間 |
| --- | --- |
| 被弾 | hit 2tick → hit_fade 3tick |
| 死亡 | 単一のdeathを96tick → 読み込み待ちの暗転（最短2tick）→ 復帰6tick |
| アドレナリン | onset 4tick → 効果時間に合わせた継続（最小1tick）→ fade 12tick |
| EMP | 3 + 4 + 6 + 10 = 23tick |
| PDA | switch 12、power 16、boot 24、map 46、close 110、rise 118、finished 142tick。最後のエフェクトなしの段を含め143tick |
| ロア | 2050tickで戻り始めてコールバック。intro_1〜6を各8tickかけ、2098tickで終了 |

アドレナリンの余韻はfadeの自然終了時だけ開始し、最後の心拍からの間隔を維持する。置換・死亡・読み込み待ち・瀕死等で打ち切る条件も維持する。

## 送信

通常更新では実際の`postEffects().values()`と構成結果を比較し、違う場合だけ`set`する。送信済みの独自キャッシュに依存せず、他プラグインが加えたエフェクトも次回の構成に残す。

ワールド読み込み完了時は構成を反映してから`update`で強制再送する。参加・退出・停止の明示的な掃除では、iem名前空間だけを除いた構成を送る。濡れ具合とマズルの既存チャンネル、通信形式は変更していない。

## 検証

- `PostEffectStackTest`: 全層の順序、grade/controlとまぶしさの条件、外部の効果・重複の保持、待機中の表示。
- `ScreenEffectPlaybackTest`: 待機・停止・継続時間、心拍の位相、段ごとの通知、中断、読み込み上限と死亡時の状態。
- `PostEffectTransportTest`: 変更時だけの送信、強制再送、他の効果を残す掃除、全コードのPostEffect操作の集約。
- `ScreenEffectServiceTest`: 実サービスの公開入口からのPDA/ロア/アドレナリン/EMP、被弾、読み込み後の待機と再送、コールバックからの置換/状態破棄、マズル解除。

単体テストはサーバーの時計と送信先を置き換えて実行する。実クライアントの描画やGPU負荷は別途確認する。

## 死亡ターミナル

レイド死亡は通常の死亡精算を先に行い、自動リスポーン後の死亡地点でスペクテイターとして待機する。`DeathScene`が移動・テレポート・観戦を抑止し、内部のロビー転送だけを許可する。描画と音の開始はクライアント読み込みとウォームアップを待つ（上限100tick）。

ワールド年齢の予約領域18500から描画時計を始め、96tickで暗転転送。読み込み中は18750の暗転信号を維持し、復帰時は18900へ切り替える。通常の時刻とEMPの予約領域は別に保つ。`iem:death`はこの間付け替えない。リザルトは演出終了後まで待機する。

パックは2パス（描画とblit）で、赤黒の段階背景、赤いマークと小さい英語ログ、CLIバー、走査帯、グリッチを時間制御する。文字は専用アトラスを読み、画面の傾きは入れない。約5秒の`iem:death.sequence`は本人だけへ一度再生し、終了・中断時に停止する。CC0グリッチの出所と加工済み音の記録はパック側に保存する。

途中切断・停止時はプレイヤーPDCの帰還印で次回のロビー復帰を引き継ぎ、音・画面・時計は掃除する。実サーバーでは死亡地点での再生、移動抑止、転送中の暗転、ロビー到着後の操作復帰、途中切断からの復帰を確認する。
