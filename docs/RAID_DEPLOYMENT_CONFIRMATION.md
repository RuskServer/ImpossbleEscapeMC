# レイド出撃の確認

## プレイヤーの流れ

地図のマップ選択、オートマッチ、`/raid join <mapID>`からの参加は、出撃内容の確認を挟む。
確認にはマップ名、即時出撃・途中参加・次レイド待機の区別、対象レイドの時間帯と天候、オンラインの参加者を表示する。
現在の装備・持ち物で参加する旨も本文に出す。説明はホバーに隠さない。

- 空きマップ・途中参加は「出撃する」、次の周期は「出撃待機する」で確定する。
- 「戻る」は地図に戻る。確認を開いたり戻ったりするだけでは、待機列や装備を変更しない。
- オートマッチは従来の優先順で選んだ具体的なマップを確認する。確定時に別マップへ自動選択し直さない。
- パーティーはリーダーが同行者を確認する。メンバー全員へ別の承認操作を追加するものではない。
- 既に待機しているマップの再クリックによる取消は従来どおり即時。確定済みの待機列が周期で出撃する際には再確認しない。
- 管理用の周期強制開始と再接続によるレイド復帰も対象外。

既存の地図ダイアログから端末色の確認ダイアログへ遷移する。PDAホームは引き続きチェストGUI。
新しいリソースパック素材は不要。

## 状態変更と保護

`RaidDeploymentApproval`はプレイヤーの画面セッションに紐付いた一度限りの識別子を持つ。120秒で失効する。
承認対象はマップ、参加方式、周期、現地条件、リーダー、パーティー構成、オンライン参加者、本人の現在の待機先。
確定直前に読み直し、変わっていれば新しい識別子で再確認する。マップが消えた場合やリーダー資格を失った場合は地図へ戻して知らせる。
待ち時間が減るだけでは再確認させない。

確認中は地図の定期更新で上書きせず、古い地図ボタンの参加操作も受け付けない。
二重承認・別の画面の識別子を拒否し、確定後に既存の`RaidModule.joinQueue`で装備容量・持込上限・レイド参加状態・再参加制限を再判定する。
切断・死亡・別インベントリの表示・停止で画面セッションを破棄する。失効後は地図へ戻す。

## 確認

`RaidDeploymentApprovalTest`は一度限りの同意、古い識別子と期限境界、マップ・参加方式・周期・天候・リーダー・構成・接続状態・待機先の変更、コピーした参加者一覧、本文の表示項目を検証する。
`RaidConditionsTest`、`RaidRotationTest`、`PdaHomeTest`も回帰確認する。
実機では地図とオートマッチの両方から、戻る・Esc・確定・途中参加・次周期待機・パーティー変更・装備容量不足を確認する。
