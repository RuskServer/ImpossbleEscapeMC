# 隠れ家の強化素材表示

各設備の次の1段階に必要な素材を、クエスト品と同じ送信時の表示で案内する。未設置はLv.1、設置済みは次のレベル、最大レベルなら対象外。HideoutFacilityの素材定義を直接使い、将来の全レベルや製作レシピの材料は対象にしない。素材定義のない設備・お金だけの設備について架空の素材は作らない。前提設備待ちでも素材の準備はでき、該当する用途には「前提設備待ち」を付ける。

クエストは従来の金色、隠れ家は水色の見出し。同じアイテムが両方に必要なら併記する。隠れ家の用途は設備・次レベル・必要数、末尾は所持数に対する合計必要数と不足数を表示する。例えば2設備がボルトを4個・2個必要とし、所持2個なら合計6・不足4として数える。所持2個を設備ごとに二重計上しない。

不足中のみ隠れ家用途の光を追加し、必要数を満たしたら「確保済み」とする。クエスト側で使えるアイテムなら、隠れ家が確保済みでもクエストの光を維持する。元々のエンチャント等による光は消さない。クエスト固有のFIR・カテゴリー等の条件は維持し、隠れ家にはFIR条件を追加しない。支給品は従来の納品不可判定により強調しない。

個数はMaterialDeliveryとHandInPlacesの共通集計で、持ち物、持ち物内のバッグ、オフハンドのバッグ、スタッシュとそのバッグを含める。開いたバッグの保存前の中身も対象。漁り・スタッシュのバックパックオーバーレイでは、表示用の欄を所持品として二重に数えず、本来の持ち物とセッション内の装備バッグを数える。この読み取り用ビューを実際の消費元として流用しない。所持数は用途ごとの予約ではなく、クエストと隠れ家のどちらかで消費すると次の更新で他方の表示にも反映される。

メインスレッドで20tickごとに需要と所持数をまとめて集計し、変更不可のスナップショットをパケット処理へ渡す。個々の送信パケットでバッグやスタッシュを読み込まない。表示内容はItemNeedPresentation、需要集計はHideoutMaterialNeeds、送信時の書き換えはQuestItemHighlighter。

サーバー上のItemStack、Lore、PDC、数量を変更しない。送信用コピーにだけ説明と光を追加する。クリエイティブは対象外。SET_SLOT、WINDOW_ITEMS、SET_PLAYER_INVENTORY、SET_CURSOR_ITEMの既存経路に対応し、必要がなくなった時も原本の表示へ戻す。

需要・個数が変わった時のplayer.updateInventoryによる全体再同期を廃止し、現在開いているメニューとカーソルについて表示が変わった欄だけを再送する。メニューの状態IDを維持し、関係ない銃・装備のスロットには送らない。新しく解決したデータパックのアイテム種別は、そのIDだけを全プレイヤーの更新に反映する。

検証: HideoutMaterialNeedsTest（次段階・最大レベル・必要数の合算・所持数・前提・不変スナップショット）、MaterialHighlightTest（色・併記・確保済み・FIR・光の優先）、LootMaterialViewTest（実際の非表示欄の復元と読み取りコピー）、MaterialDeliveryTest、HandInStoreTest。ビルドとこれらのテストが通過。実クライアント上の tooltip の見た目、漁り・売却・強化後の反映、銃のアニメーションへの影響は実機確認待ち。
