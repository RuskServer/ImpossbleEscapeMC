# 開閉するロッカー

提供された `locker_command.txt` の14部品をBlockDisplayでそのまま再現する。ドロワーと同じく、床中央を配置原点として各部品の元の変換行列へ向きと扉の回転を掛ける。固定部6部品と扉8部品を使用し、扉には取っ手、下側パネル、上側の通気部分を含む。左側の蝶番から手前へ90度、10tickで開く。素材は薄灰色コンクリートと上面の滑らかな石ハーフブロック。

1台あたりBlockDisplay 14個、Interaction 1個、衝突用バリア2ブロックを使う。以前のItemDisplay 2個から描画エンティティが増えるため、大量配置時の負荷は実機で確認する。常時アニメーションタスクはなく、開閉時だけ扉部品の表示変換を送る。ロッカー表示に専用リソースパックモデルは不要。パック側の旧モデルは参照しない。

既存登録は再起動・チャンク再読込で古い表示部品だけを片付けて再生成する。操作用InteractionのPDCにある中身・検索済み欄・補充世代は従来どおり復元する。今回の表示変更を理由にルートを再抽選しない。

## 設置・削除

OPが対象マップのワールドで実行する。

```text
/loot lockeregg <mapId>
/loot locker place <mapId>
/loot locker list <mapId>
/loot locker remove
```

専用エッグはブロックの面をメインハンドで右クリックして繰り返し設置できる。消費しない。オフハンド・空中・エンティティへの操作では動物を生成しない。直接設置コマンドは5ブロック以内で見ている床の上へ置く。取っ手は設置者の方へ向くよう4方向に丸める。

形状は幅1、奥行1、高さ2.25ブロック。設置時は縦3ブロックを空ける。衝突用バリアは下2ブロックで、最上部0.25は表示のみ。扉の可動領域は視覚表現で、開いた扉そのものに追加の物理衝突はない。前面にも開閉の空間を取る。

削除は上か下のバリアを見てコマンドを実行するか、既存の `/loot remover` で右クリックする。操作判定への削除ツールの右クリックにも対応する。GUIを閉じ、登録・表示・操作判定・上下のバリアを消す。中身はドロップしない。

## 中身と補充

1台につき27スロット。同じロッカーを複数人が開いた場合は同じ実インベントリを共有する。最初の閲覧者で開き、最後の閲覧者が閉じると扉が戻る。空のロッカーも同じ形・同じ開閉で漁れる。

設置時と補充時に、各ロッカーを独立して次の確率で抽選する。

| 結果 | 確率 |
| --- | --- |
| 空 | 75% |
| `standard_crate` | 約8.33% |
| `medical_case` | 約8.33% |
| `ammo_case` | 約8.33% |

「必ず4台につき1台」ではなく、平均で4台に1台が中身の抽選対象になる。対象クレートの通常のルート表・抽選数を使う。レイド開始時のマップ補充、`/loot refill`、対象を見て `/loot refill this` で再抽選する。開け直すだけでは再抽選しない。

マップJSONの `lootLockers` にID・座標・向き・補充世代を保存する。中身の有無とクレートの選択はIDと世代で決まり、サーバー再起動やチャンク読込で変わらない。実アイテムと検索済み欄はInteractionのPDCに保存し、取得・閉じる・アンロード・停止時に保存する。未読込ロッカーは世代だけ更新し、次の読込で補充する。補充のためにチャンクを同期ロードしない。

壊れたインベントリの保存データは勝手に再生成せず、利用不可としてログに出す。SearchGUIの検索演出・音・FIR・タスク品通知・共有取得・部分取得・バックパック・移動保護は既存のまま使う。

## 検証

`LockerModelTest` は4方向の蝶番位置・開口方向・固定部不動、旧マップ互換、負座標と補充世代の保存を確認する。`LockerLootRollTest` は12万台の空率・3種類の比率、再読込での選択維持、世代変更での再抽選を確認する。元14部品の配置と開閉を数値で照合する。

実ゲームでは設置、扉・取っ手の開閉、空と中身ありの漁り、複数人での共有と開閉、部分取得、補充、再起動・チャンク再読込、削除ツール、大量配置時の負荷を確認する。Minecraft上の実機確認は別途必要。

## ブロックディスプレイ方式の検証

LockerModelTestは14部品・8扉部品、4方向の閉じたパネル位置、外へ開く向き、固定部不動、高さ0〜2.25、回転で部品が伸縮しないこと、登録と補充世代の保存を確認する。LockerLootRollTestは25%と3種類の分布を確認する。ビルド・計算テストは通過、実機の見た目・既存個体の再読込と多数配置時の負荷は未確認。
