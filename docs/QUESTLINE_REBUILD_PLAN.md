# 勢力設定とクエストライン再構築計画

更新日：2026-11-01（第一段階実装済み・実地検証前）

この文書は、運営内で合意した勢力設定と、それをクエストへ落とし込むための設計案をまとめたもの。
「確定設定」は世界観の基準とし、「設計案」は実装前に調整できる。クエスト名・件数・報酬・トレーダーの経歴は、この文書だけでは確定しない。

## 1. 確定設定

### 1.1 プレイヤーとノヴォザリエ

- 舞台は封鎖されたノヴォザリエ経済特区。Spectreはこの地で次世代軍事技術を研究していた。
- プレイヤーは契約していたPMCから切り捨てられた「否認された資産」。企業の正式な指揮下へ戻った状態にはしない。
- Spectreの技術や研究データは外で高値が付く。しかし、持ち出すにはまず生きて脱出する必要がある。
- 企業が傭兵や物資を送り込む構図と、プレイヤーが企業から直接・正式に依頼されることは区別する。トレーダーを通して仕事と利害が届く。

### 1.2 三勢力の最終目的

| 勢力 | 最終目的 | 行動と関係 |
| --- | --- | --- |
| Spectre | 技術発展および研究施設の保全 | 研究を継続できる設備・資材・防衛能力を確保する。単に資料を隠すことや、施設から撤退することを最終目的にはしない。 |
| 国連軍 | Spectreの技術を強引に奪取して自軍へ転用し、Spectreを管理下に置く | 競合企業群との関係を維持しながら動く。稀に汚職も行われる。 |
| 競合企業群 | 利益追求のため、Spectreの技術を奪取する | 国連軍と取引する一方、裏では他PMCへ物資を投下し、Spectre部隊にも物資を与えている。評判のよい取引だけを行う集団ではない。 |

国連軍と競合企業群は協力関係にある。ただし、前者は技術の軍事転用とSpectreの管理、後者は利益を目的としており、常に同じ結論を望むわけではない。

競合企業群を、一社の統一された意思で動く組織として断定しない。個別企業や取引相手の名前・内部対立は、必要になった段階で別途設定する。

### 1.3 勢力間の関係

- **国連軍 → Spectre**：技術の奪取・軍事転用と、組織を管理下に置くことを狙う。
- **競合企業群 → Spectre**：利益になる技術を狙う。一方で、Spectre部隊への物資供与も行う。
- **国連軍 ↔ 競合企業群**：関係を維持して取引する。公的な説明と実際の取引内容が一致するとは限らない。
- **競合企業群 → 他PMC**：裏で物資を投下する。プレイヤー以外のPMCにも支援が届く。
- **Spectre部隊 ← 競合企業群**：物資が渡っている。ただし、個々の供与の狙い・条件・受け手の認識は未確定。

物資供与を見つけただけで「競合企業とSpectreは同盟」「Spectre全体が買収されている」と結論付ける描写は避ける。供与の理由は、具体的な依頼や記録を作る際に決める。

### 1.4 トレーダーの立ち位置

| トレーダー | 加担する側 | クエスト設計上の役割 |
| --- | --- | --- |
| Kovacs | 競合企業群 | 技術・試作品・搬送情報の回収と、武器・部品・物資の流通を仲介する。 |
| Pharmakon | 国連軍 | 医療・補給を入口に、国連軍が必要とする調査、技術回収、施設把握へつなぐ。 |
| Bastion | Spectre | 研究施設の保全、設備復旧、研究継続、防衛・補給に必要な仕事を取り次ぐ。 |

所属先への正式な役職、個人的な信条、過去の経歴は未確定。例えば「Bastionは元補給担当」「Pharmakonは正式な軍医」などは、現時点では設計上の候補であり確定設定に含めない。

## 2. 今回の範囲

専用資料・新アイテム・新しい操作設備を用意せず、既存51件を使って再構築する。現行のアイテム、確認済みの調査地点、納品・討伐・脱出・取引解放だけで実装できる計画を第一段階とする。

- 第一段階のカタログ・報酬・移行処理を実装済み。移行は更新jar導入後のプレイヤーデータ初回読込時に行う。この開発作業では実サーバーのデータを変更しない。
- 主線・支線と四段階は、まず既存クエストの前提と文章で表現する。専用の章UIや新しい進行システムを実装の必須条件にしない。
- 三者の件数を無理に揃えない。既存51件を全件分類し、Pharmakonだけを水増しして帳尻を合わせない。
- 専用資料の回収、設備操作、地区内討伐、実際の護送・輸送は将来拡張へ回す。
- 既存のUSB・RAM・GPUは、そのアイテムとして扱う。通常のUSBを特定の機密資料だと断定したり、専用クエスト品があるような目標を書いたりしない。

## 3. 現行で判定できることと限界

| 内容 | 今回の扱い |
| --- | --- |
| 既存アイテムのFIR納品 | 利用する。弾薬の口径・貫通クラス、防具クラス、既存カテゴリによる指定も利用可能。 |
| 既存地点への到達 | 利用する。現状はワールドと距離による判定で、レイド参加・遮蔽・操作・滞在時間の保証はない。 |
| SCAV討伐 | マップ、武器、武器種、距離、ヘッドショット条件を利用する。 |
| 特定の建物・地区内だけの討伐 | 現行では判定できないため使わない。「キャンプ周辺だけで倒せ」などの指定はしない。 |
| 任意・指定マップからの脱出 | 利用する。受注後の累計で、他の目標とは独立して進む。 |
| 調査後・納品物取得後、同じレイドで生還 | 現行では保証できないため使わない。目標の記述順を達成順序と扱わない。 |
| 複数マップからの脱出 | 工場・沿岸の目標を別々に置くことで表現できる。任意脱出2回では代用しない。 |
| 受注以前に拾ったFIR品 | 現行納品では利用できる。「受注後に現地調達した品だけ」という条件にしない。 |
| 取引解放 | 報酬表示と販売側の必要クエストを対応させる。現金とEXPの報酬も既存機能で調整する。 |
| 輸送隊・施設の復旧・技術の転用 | 依頼文の用途・背景として表現する。実際にNPCや施設状態が変化したとは表示しない。 |

「地点を確認する」「工場から脱出する」が同じ依頼にあっても、先に脱出目標を終え、次の出撃で地点を訪問できる。今回はこの仕様を維持し、文章も「調査と帰還をそれぞれ達成する」とする。

## 4. 三者の進行と対立

| 段階 | Kovacs：競合企業側 | Pharmakon：国連軍側 | Bastion：Spectre側 |
| --- | --- | --- | --- |
| 1：生存と接点 | 帰還、工具、通信資材を揃え、外部の買い手へつながる。 | 医療品と衛生用品を集め、国連側の補給を支える。 | 工場の搬送設備を確認し、施設保全に必要な資材・装備を集める。 |
| 2：物資の流通 | 東西の弾薬や部品を集め、複数の相手へ回せる在庫を作る。 | 工場の休憩所・研究室を調べ、医療・施設調査を進める。 | 沿岸倉庫と運搬能力を確認し、研究施設への補給を支える。 |
| 3：技術と装備 | 記録媒体・電子部品を集め、買い手の技術取得へ協力する。 | 工場の調査と活動継続に必要な物資を確保し、技術利用・管理の足場にする。 | 軍事キャンプ・電波塔の状態を確認し、制御系や防護装備を確保する。 |
| 4：利益・管理・保全 | 技術・国連由来装備の評価や取引を進める。 | 護送路確保を名目とした戦闘と物資備蓄を通じ、国連側の活動基盤を広げる。 | SP-Vの調達へ進み、技術発展と研究施設保全を支える。 |

裏取引は依頼文と後続タスクの説明で段階的に示す。存在しない搬送票や積荷番号を回収したことにはしない。例えばKovacsが「次の荷は国連向けだ」「別口の投下にも回す」「Spectreの部隊にも渡る」と取引の一部を口にする場面を作れるが、具体的な台詞と取引事情は後で確定する。

Pharmakonの国連軍との関係は序盤から明かしてよい。医療の話だけで最後まで引っ張らず、後半の説明で技術の転用や施設管理への意図を示す。汚職の描写は一部に限り、本人の関与や全組織の常態とは断定しない。

### 調整の根拠

## 8. テスト段階での移行方針（確定）

運営内テストプレイ段階のため、旧クエストの進捗互換は不要。**販売解放の権利のみを引き継ぎ、旧クエストの受注・進行・完了履歴はリセットする。** 旧定義の並行運用や、新主線への進捗変換は実装しない。

| 対象 | 扱い |
| --- | --- |
| クエストで獲得した販売・交換の解放資格 | 引き継ぐ。旧クエスト完了履歴を削除しても失われないよう、先に独立した解放記録として保存する。 |
| 旧クエストの受注状態・目標進捗・完了履歴 | 引き継がない。新ラインを最初から受注できる状態へ戻す。 |
| 旧ラインの主線・支線の前提達成 | 引き継がない。販売解放の保持によって、新ラインを完了済み扱いにはしない。 |
| プレイヤーレベル・EXP・所持金・所持アイテム・Hideoutなど | 今回のクエスト移行では変更しない。既に受け取った報酬も回収しない。 |
| 新ラインの報酬 | 新ラインで条件を満たして完了した際に通常どおり支給する。過去報酬との差額補填や、リセット時の自動支給は行わない。 |
| 商品の必要レベル・価格・購入上限 | 通常どおり適用する。保存するのはクエストによる解放資格であり、購入条件全体の免除ではない。 |
| 日次購入済み数 | リセットしない。クエスト移行で在庫制限を回避できないようにする。 |

### 実装時の手順

1. 旧クエストと旧販売定義が参照できる状態で、旧完了記録から獲得済みの解放資格を抽出する。
2. トレーダー・商品・現金購入／交換を識別して解放資格を永続保存する。PVS-14の現金販売と交換など、別々の条件で開く取引を混同しない。
3. 解放記録の保存を確認してから、旧クエストの受注・進行・完了履歴を消去する。
4. 以後のクエスト側販売条件は「保持した解放資格、または新ラインの解放条件を達成」で判定する。
5. プレイヤーごとに移行バージョンを保存し、再起動や再実行で新ラインの進捗まで再び消さないようにする。

オフラインのテスト参加者も対象とする。バックアップを用意し、途中失敗した場合に解放情報を失わず再実行できる順序で保存する。

既存IDの再利用は可能。旧進捗を流用しないため、新旧目標のインデックスを一致させる必要はない。ただし、新定義を旧進捗に適用してから移行することは避ける。

移行コードは実装済みだが、この開発作業では実データのリセットは行わない。更新jarを実サーバーへ導入すると、既存データは初回読込で一度だけ移行される。オフラインのプレイヤーは次のログインまたはデータアクセス時に対象となる。
